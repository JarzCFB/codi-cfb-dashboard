# What historical data is actually available?

Run from the repository checkout:

```bash
python v4_historical_gap.py --output v4_historical_gap.json
```

This inspects two **existing** datasets:

- `backtests/v1_v2_game_results.csv`: 2024–25 historical games with
  V1 and V2 walk-forward projections and final margins.
- `prospective/graded_selections.csv`: official frozen V3 selections
  currently recorded for 2026.

The data is **not paired V3 versus V4**. Do not silently substitute a
recomputed 25%/75% blend for historical official V3 predictions, do not
pretend postgame information was available pregame, and do not fill
unknown player availability with zeros.

The JSON gives accurate coverage, observed historical V1/V2 MAE and
specific remaining requirements. No training or betting deployment
occurs. The historical V1/V2 sample is not automatically a verified
V4 feature dataset.

## Repository snapshot inventory caveat

The repository also contains timestamped files under `snapshots/2026/`, generated by `snapshot_capture.py`. Those rows contain sportsbook spread quotes and a **separate ratings-derived** `projected_home_margin` (with `ratings_input_sha256`), not a frozen official V3 calibrated 25% V1 / 75% V2 projection. They are valuable point-in-time market/rating records but **must not be relabeled as V3 pregame predictions** or used as paired V3/V4 validation. Snapshot game IDs originate with the odds provider and may not match CFBD or frozen-selection IDs without independently validated matching.

Before claiming all-game official V3 historical coverage, locate an archived source explicitly containing the contemporaneous V3 calibrated output and its capture timestamp, verify identity and pregame availability, and audit completeness. Otherwise leave the V3 all-game baseline unavailable.
